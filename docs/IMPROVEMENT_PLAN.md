## 2. 문제점 (심각도 순)

### 🔴 P0 — 데이터 유실: Render 무료 플랜은 디스크가 휘발성

**증상 (라이브 서버에서 검증됨)**: `/api/notices` 응답이 `{"notices":[],"total":0}` —
운영 중 등록한 공지·현장이슈·체크리스트 기록·업로드 PDF가 **재배포/재시작 때마다 전부 삭제됨**.

**원인**: 모든 데이터가 컨테이너 내부 JSON 파일(`backend/data/*.json`)에 저장되는데,
Render 무료 플랜은 영구 디스크가 없어 배포·재시작 시 파일시스템이 초기화됨.
git push 한 번 할 때마다 직원들이 입력한 데이터가 사라지는 구조.

**영향받는 데이터**: 공지사항+첨부파일, 현장이슈/도면검토, 체크리스트 항목·체크기록,
관리자가 앱에서 업로드한 추가 PDF. (사전 탑재 PDF와 사용자 명단은 이미지에 포함되어 안전)

**해결 방안 (택1)**:
- **A안 (권장, 무료)**: 외부 무료 DB로 이전 — Supabase(PostgreSQL 무료 500MB) 또는
  Turso/Neon. `json_store.py`를 DB 어댑터로 교체하면 라우터 코드 변경 최소화.
- **B안 (유료, 가장 간단)**: Render 유료 플랜 + Persistent Disk ($7/월+디스크 비용).
  코드 변경 거의 없음 — 디스크 마운트 경로로 `DATA_DIR`만 변경.
- **C안 (임시 완화)**: 주기적으로 데이터를 GitHub에 자동 커밋 백업.
  근본 해결은 아니며 실시간성 없음.

### 🔴 P1 — 백업 부재

DB 이전 전까지는 데이터 스냅샷 자체가 없음. P0 해결 전이라도
관리자용 "전체 데이터 내보내기/가져오기" API(JSON zip 다운로드)가 필요.
재배포 직전 내보내기 → 배포 후 가져오기로 임시 운영 가능.

### 🟠 P2 — 보안 취약점

1. **사번 = 비밀번호**: 사번은 사내에서 공공연히 알려진 정보. 명단이 GitHub 저장소에
   평문 JSON으로 커밋되어 있음 (`backend/data/auth_users.json`).
2. **Admin Token이 브라우저 localStorage 평문 저장** + 모든 API 요청 헤더로 노출.
3. **세션 만료 없음**: 한 번 로그인하면 영구 유지, 서버 측 세션/토큰 검증 없음.
4. **CORS 와일드카드** (`*`): 사내 전용 앱이므로 위험도는 낮으나 개선 여지.

**해결 방안**: 저장소를 private 확인 → auth_users.json을 저장소에서 제거하고
환경변수/DB로 이전 → 로그인 시 서버 발급 토큰(단순 HMAC이면 충분) + 만료 24h.

### 🟠 P3 — 검색 품질 한계

1. **동의어/유사어 미지원**: "행거"로 검색하면 "지지금구" 청크를 못 찾음.
   `search_synonyms.json`이 존재하지만 RAG 검색(`document_rag.search`)에는 미연동.
2. **KCSC 원문보기**: 문서명 검색으로 개선했으나 여전히 "검색결과 → 한 번 더 클릭" 2단계.
   KCSC OpenAPI 키(`KCSC_API_KEY`)가 Render 환경변수에 설정되어 있는지에 따라
   live/sample 모드가 갈림 — 키 상태 정기 점검 필요.
3. **AI 캐시가 탭 단위**: 새로고침하면 캐시 소멸 → 같은 질문 재호출로 Gemini 비용 발생.
   localStorage 기반 캐시(TTL 24h)로 승격하면 비용 추가 절감.

### 🟡 P4 — 운영 안정성

1. **GitHub Actions cron 지연**: 무료 러너는 혼잡 시 10분 → 최대 30분+ 지연 가능.
   콜드 스타트가 간헐적으로 재발할 수 있음 → cron-job.org 5분 백업 ping 추가 권장 (무료, 3분 설정).
2. **RAM 512MB**: Gemini 동시 질의 + PDF 파싱 겹치면 OOM 가능성. 모니터링 필요.
3. **테스트 부재**: 자동화 테스트 0건. 최소한 라우터 스모크 테스트(pytest) 필요.
4. **네이버클라우드 서버 방치**: 101.79.23.179 (SSH 복구됨, Python/Node 설치됨, 미사용).
   과금 중이면 반납하거나, Render 대체 배포처(콜드 스타트 없음)로 활용 결정 필요.

### 🟡 P5 — 데이터 모델 불일치

현장 목록이 **두 곳에 이원화**: `auth_users.json`의 sites(로그인용 30개)와
`sites.json`의 sites(현장이슈용, 직접 등록). 체크리스트 드롭다운은 둘을 병합해 보여주지만
이름 변경 시 한쪽만 바뀌는 정합성 문제 소지. 단일 현장 마스터로 통합 필요.

### ⚪ P6 — 사용성 개선 여지

1. PWA 제거됨 → 오프라인 미지원 (지하층 현장에서 불편). npm 환경 정상화 후 재도입 검토.
2. 다크모드 토큰은 완비됐으나 설정 화면의 토글 → `data-theme` 연동 확인 필요.
3. 체크리스트 결과 내보내기(엑셀/PDF 보고서) 없음 — 감리 제출용 수요 예상.
4. 공지 팝업 "다시 보지 않기"가 기기(localStorage) 단위 — 기기 바꾸면 재표시.

## 3. 수정 계획 (단계별)

### Phase 1 — 데이터 보호 (최우선, ~2일)
| # | 작업 | 내용 |
|---|---|---|
| 1-1 | 데이터 내보내기/가져오기 API | `/api/admin/export`(zip), `/api/admin/import` — 재배포 전후 수동 보존 |
| 1-2 | 저장소 선택 결정 | Supabase(무료) vs Render Disk($7/월) — **사용자 결정 필요** |
| 1-3 | 스토리지 어댑터 교체 | `json_store.py` → DB 어댑터. 라우터 인터페이스 유지 |
| 1-4 | 마이그레이션 검증 | 기존 JSON → DB 이전 스크립트 + 왕복 테스트 |

|---|---|
| 2-1 | auth_users.json을 git 추적에서 제거, DB/환경변수로 이전 |

| 2-3 | 저장소 private 여부 확인 및 커밋 이력 정리 |

### Phase 3 — 검색·비용 (~1일)
| # | 작업 |
|---|---|

| 3-3 | KCSC_API_KEY 상태 점검 엔드포인트 + 관리자 화면 표시 |

### Phase 4 — 운영 안정화 (~1일)
| # | 작업 |
|---|---|

| 4-3 | 현장 마스터 단일화 (auth sites ↔ site_issues sites 통합) |
| 4-4 | 네이버클라우드 서버 처리 결정 (반납 or 이전) — **사용자 결정 필요** |

### Phase 5 — 사용성 (여유 시)

- 다크모드 토글 동작 검증
